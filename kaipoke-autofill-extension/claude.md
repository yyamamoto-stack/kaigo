# claude.md — カイポケ自動入力拡張機能 プロジェクト絶対ルール

このファイルは、本 Chrome 拡張機能（カイポケ「訪問介護計画書 新規追加」自動入力ツール）
の開発・保守を担当するすべての開発者（および AI アシスタント）が**必ず遵守すべき絶対ルール**を定義します。
このルールに反するコードは、いかなる理由があってもマージ・デプロイしてはいけません。

---

## 0. このプロジェクトの目的と前提

- カイポケ（介護業務システム）の「訪問介護計画書 新規追加」画面に対して、
  事前に用意した JSON データを**画面操作（DOM 操作）で自動入力**する Chrome 拡張機能を提供する。
- 目的はあくまで「事務スタッフの手入力の負担軽減」であり、**最終確認と登録は必ず人間が行う**。

---

## 1. ⚠️ カイポケ利用規約・コンプライアンス最優先ルール（最重要）

> カイポケ運営からの警告により、以下はアカウント BAN の対象となります。
> **本ルールに違反する実装は絶対に禁止です。**

### 1-1. 【API 禁止要件】内部 API への直接通信の全面禁止
- `fetch()` / `XMLHttpRequest` / `navigator.sendBeacon()` / `WebSocket` などを用いた
  **カイポケ内部サーバーへの直接通信は一切行わない。**
- 内部 API の解析・リバースエンジニアリング・エンドポイント推測は禁止。
- 本拡張機能は**「純粋な DOM 操作（画面上のクリックとテキスト入力）」のみ**で構成する。
  人間がブラウザ上で行う操作以外の手段でデータを送受信してはならない。

### 1-2. 【安全規約要件】人間の操作スピードの模倣（必須スリープ）
- すべてのアクション（クリック / 入力 / タブ切り替え / モーダル操作）の**間**に、
  必ず `sleep(500)` 〜 `sleep(1500)` の**ランダムな待機時間**を挟むこと。
- ループ処理（複数サービスの連続入力など）でも、各反復の間に必ずスリープを入れる。
- 短時間での大量リクエスト（サーバーへの過度な負荷）に相当する挙動を発生させないこと。

### 1-3. 【暴走防止要件】タイムアウトと安全停止
- DOM の出現待機 `waitForElement` には**必ずタイムアウト（既定 10 秒 = 10000ms）を設ける**。
- 要素が見つからない場合は、**処理を安全に停止**し、`alert()` 等でユーザーに明確に通知する。
- 想定外の状態（要素なし・複数マッチ・画面遷移失敗）では**続行せず必ず中断**する。
  「とりあえず先に進む」実装は禁止。

## 2. 技術規約

### 2-1. Manifest V3 の厳守
- `manifest.json` は必ず **Manifest V3**（`"manifest_version": 3`）で記述する。
- `background` は使用する場合 Service Worker（`"service_worker"`）とする。
- V2 固有の記法（`browser_action`、`background.scripts` の永続ページ等）は使用禁止。

### 2-2. Vanilla JS のみ
- フレームワーク・ライブラリ（React / Vue / jQuery / lodash 等）は**一切使用しない**。
- ビルドツール（webpack / vite 等）に依存しない、素の JavaScript（ES2020 程度）で記述する。
- 外部 CDN の読み込み・外部スクリプトの動的 import は禁止。

### 2-3. 権限は最小限
- `manifest.json` の `host_permissions` は**カイポケの URL のみ**に限定する。
- `<all_urls>` やワイルドカードで無関係なサイトに権限を与えてはならない。
- 使用する権限は `activeTab` / `scripting` など必要最小限にとどめる。

### 2-4. 親子ウィンドウ（ポップアップ）の構成
- カイポケの「サービス設定」は**別ウィンドウ（ポップアップ, `.../plan_document/MEM…`）**で開く。
- そのため `content.js` はカイポケ全ページに注入され、URL で「メイン画面／ポップアップ」の役割を判定する。
- 親子ウィンドウをまたぐ順序制御は `background.js`（Service Worker）が担う。
  - `background.js` は**中継と待機のみ**。fetch 等の外部通信・DOM 操作は行わない。
  - 実際の入力・スリープ・待機は各 `content.js` が担当する（本ルールの 1-1／1-2／1-3 を厳守）。
- ポップアップブロックが有効だと開かないため、ユーザーへ許可を促す（README 参照）。

## 3. コーディング規約

### 3-1. 【セレクタの分離】ハードコード禁止
- DOM セレクタ（CSS セレクタ・XPath・要素名・ラベル文言など）を
  ロジック中に**直接ハードコードしてはならない**。
- すべてのセレクタは `content.js` 上部の `const SELECTORS = { ... }` に**集約**する。
- カイポケの UI 変更に対しては、原則 `SELECTORS` の修正のみで復旧できる構造を保つこと。
- ロジック関数はセレクタの中身を知らず、`SELECTORS.xxx` を参照するだけにする。

### 3-2. コアスキルの共通化
- 要素待機・値設定・クリック・遅延といった基礎操作は `skills.md` に定義した
  実装（`waitForElement` / `setNativeValue` / `safeClick` / `sleep`）を用いる。
- 同等機能を個別に再実装しない（挙動のばらつき・スリープ漏れを防ぐため）。

### 3-3. 可読性とコメント
- すべての関数・処理ブロックに**日本語のコメント**を豊富に付ける。
- 保守担当者（システム管理者）がセレクタと処理フローを追えることを最優先とする。

### 3-4. 値の入力は必ずネイティブイベントを伴わせる
- React 等の制御コンポーネントでも値が確実に反映されるよう、
  値の設定は `setNativeValue`（`input` / `change` イベントを強制発火）を用いる。
- `element.value = x` の代入だけで済ませない。

---

## 4. やってはいけないこと（禁止事項まとめ）

- ❌ `fetch` / `XMLHttpRequest` 等によるカイポケ内部 API への通信
- ❌ スリープ（`sleep(500)`〜`sleep(1500)`）を省略した連続操作
- ❌ タイムアウトのない無限待機
- ❌ 要素が見つからないまま処理を続行する実装
- ❌ セレクタのロジック中へのハードコード
- ❌ Manifest V2 記法・外部ライブラリ・過剰な権限
- ❌ 自動での最終「登録（保存）」ボタン押下（※最終登録は人間が行う。詳細は README 参照）

---

## 5. 変更時のチェックリスト

コードを変更したら、以下を必ず確認すること。

- [ ] 内部 API 通信（fetch/XHR）を追加していないか
- [ ] すべてのアクション間に `sleep(500〜1500)` が入っているか
- [ ] `waitForElement` にタイムアウトがあり、失敗時に安全停止するか
- [ ] 新規セレクタを `SELECTORS` に集約したか
- [ ] Manifest V3 / Vanilla JS を維持しているか
- [ ] 権限がカイポケ URL のみに限定されているか
