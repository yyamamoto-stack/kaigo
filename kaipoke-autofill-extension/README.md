# カイポケ 訪問介護計画書 自動入力ツール（Chrome拡張機能）

カイポケの「**訪問介護計画書 新規追加**」画面に、事前に用意した JSON データを
**画面操作（DOM 操作）のみ**で自動入力する社内向け Chrome 拡張機能です。

> ⚠️ **このツールは「下書き入力」までを行います。**
> 最終的な「登録（保存）」は、必ず人間が目視確認のうえ手動で行ってください。

---

## 🛡️ 最重要：カイポケ利用規約・コンプライアンス

カイポケ運営からの警告により、**以下はアカウント BAN の対象**です。本ツールはこれを回避する設計になっています。

| 禁止事項 | 本ツールの対応 |
| --- | --- |
| サーバーへの過度な負荷（短時間の大量リクエスト） | すべての操作の間に `sleep(500)`〜`sleep(1500)` のランダム待機を挿入し、人間の操作スピードを模倣 |
| 非公開 API への直接アクセス・解析 | `fetch` / `XMLHttpRequest` 等の内部通信を**一切行わず**、純粋な DOM 操作（クリック・入力）のみで構成 |
| 暴走（無限ループ・想定外状態での続行） | 要素待機に 10 秒のタイムアウトを設け、見つからなければ**安全停止＋アラート通知** |

詳細な開発ルールは [`claude.md`](./claude.md)、コア関数の実装は [`skills.md`](./skills.md) を参照してください。

## 📁 ファイル構成

| ファイル | 説明 |
| --- | --- |
| `manifest.json` | 拡張機能定義（Manifest V3、権限はカイポケ URL のみ、background 登録） |
| `popup.html` / `popup.js` | JSON 貼り付け UI と、background への開始依頼 |
| `background.js` | 親（メイン画面）と子（サービス設定ポップアップ）の content.js を仲介する調整役（Service Worker） |
| `content.js` | DOM 操作のコアロジック（先頭に `SELECTORS` を集約、URL で役割判定） |
| `claude.md` | プロジェクトの絶対ルール（コンプライアンス／技術規約） |
| `skills.md` | コアスキル（`waitForElement` / `setNativeValue` / `safeClick` / `sleep` ほか）の実装定義 |
| `README.md` | 本ファイル（運用マニュアル・部署別の役割） |

> ℹ️ **v2 の重要な変更**：カイポケの「サービス設定」は**別ウィンドウ（ポップアップ）**で開くため、
> それを跨いで順序制御する `background.js` を追加し、JSON 構造を実画面に合わせて拡張しました。

## 🚀 インストール（初回デプロイ）

1. Chrome で `chrome://extensions` を開く。
2. 右上の「**デベロッパーモード**」を ON にする。
3. 「**パッケージ化されていない拡張機能を読み込む**」をクリック。
4. この `kaipoke-autofill-extension` フォルダを選択する。
5. ツールバーに拡張機能アイコンが表示されれば完了。

---

## 🖱️ 使い方（事務・入力担当スタッフ向け）

1. カイポケにログインし、「**訪問介護計画書 新規追加**」画面を開く。
2. **⚠️ ポップアップブロックを許可**する（サービス設定は別ウィンドウで開くため）。
3. ブラウザ右上の拡張機能アイコンをクリックしてポップアップを開く。
4. サービス提供責任者から受け取った **JSON データ**をテキストエリアに貼り付ける。
   （フォーマット確認用に「サンプルを挿入」ボタンあり）
5. 「**自動入力を実行**」を押す。基本情報 → 各サービス（別ウィンドウ）→ 援助内容タブ、の順で自動入力される。
6. **⚠️ 入力完了後、必ず目視で内容を確認**し、誤りが無ければ
   **作成状態を「作成済」にして、自分でカイポケの「登録する」ボタンを押す**。

### JSON データの形式（v2：実画面対応）

`basicInfo`（基本情報＋援助目標＋説明欄）と `services`（サービスの配列）を持つ階層構造です。
日付は**和暦**、`services[].supportDetails` は**援助内容の行の配列**です。
select 項目（適用期間・事業所・ケアマネ・サービス種類・サービス項目）は
**カイポケ登録値と完全一致**する文字列にしてください。詳細は Drive のフィールド定義書を参照。

```json
{
  "basicInfo": {
    "createdDate": "令和8年7月13日",
    "insurancePeriod": "令和8年2月2日から令和9年2月28日まで",
    "author": "山本 禎典",
    "careOffice": "向日葵 介護センター",
    "careManager": "矢部 房子",
    "issues": "…", "longTermGoal": "…", "shortTermGoal": "…",
    "personFamilyHope": "…", "notes": "…",
    "explainDate": "令和8年4月8日", "explainer": "麻生 操子"
  },
  "services": [
    {
      "insuranceType": "保険内",
      "serviceType": "身体生活",
      "serviceOffice": "訪問介護 いっぽ(2371005485)",
      "serviceContent": "入浴介助・生活援助",
      "units": "75",
      "startTime": "08:00", "endTime": "09:15",
      "additions": [],
      "provisionCycle": "毎週", "provisionNthWeek": null,
      "provisionDays": ["月", "水", "金"],
      "supportDetails": [
        { "category": "身体", "item": "全身浴", "content": "入浴介助または清拭", "requiredTime": "20", "notes": "" }
      ]
    }
  ]
}
```

## 📝 実績の備考へ サ責確認コメントを一括追記（v2.20.0）

従業員別の**月間シフト割当一覧**（MEM097811・介護保険/障害の実績が同じ画面に並ぶ）で、
従業員が作業日に入力した備考コメントに対し、担当サ責の「**コメントを見ました**」の記録を
既存コメントの手前に一括で追記する機能です。

追記されるコメント（1行形式・この後ろに改行して既存コメントが続く）:

```
【サ責】石原裕子2026/07/17　10:18
```

- **対象行**＝**今日と昨日の作業分**で、**従業員のコメントが入っている行のみ**。
  それ以外の日付・コメント未入力の行には触らない（毎日実行する運用。1日飛んでも昨日分でカバーされる）。
- **サ責名**＝その行の**利用者の担当サービス提供責任者**。
  利用者売上表（03レセプト・経理部）のAS列「担当者」に基づく対応表で決まる。
  対応表はサイドパネル下部のテキスト欄（1行=「利用者名：サ責名」）で編集でき、自動保存される。
  **担当が変わったらこの欄を直す**こと。
- **初回セットアップ**：対応表は個人情報（利用者名簿）のため拡張機能には同梱していない。
  Drive の `08システム部\管理者向けアプリ開発担当\20260716_利用者担当サ責対応表.txt` の一覧を
  コピーして対応表欄へ貼り付ける（保存先はこの PC の chrome.storage のみ）。
- 備考ポップアップの行には利用者名が無いため、メイン一覧の実績側と
  「日付＋サービス内容＋時間＋保険区分」で突き合わせて利用者を特定する。
  特定できない行・対応表に無い利用者の行は**書き込まずに警告表示**する（手動入力）。
- **日付**＝その行の**作業日の翌日**（例：7/16の作業→2026/07/17）
- **時刻**＝10:00〜10:30 のランダム。**同じ日付には同じ時刻**が使われる
  （従業員を切り替えて何回実行しても、その日のうちは同じ時刻になる）
- 既に**同じサ責・同じスタンプ日付**のコメントが入っている欄はスキップ（再実行しても二重追記しない。
  他のサ責のコメントが入っている欄には追記する）
- ①のスキャンでは「どの行に何を追記するか」の計画がそのまま表示されるので、実行前に確認できる

### 画面の仕組み（実DOM確定済み）

一覧の備考列は表示専用で、編集は【実績】ヘッダの「備考」ボタン →
備考一括入力ポップアップ（`formRegistCaptions:tableRemark:N:remark`）で行う構造。
本機能はこの「備考」ボタンのクリック → ポップアップの各欄への追記までを自動で行い、
**保存の「登録する」ボタンは押さない**（人間が押す）。

### 使い方

1. カイポケで対象従業員の**月間シフト割当一覧**を開く。
2. サイドパネルの「**① 備考欄を確認**」を押す（読み取りのみ。何も書き込まない）。
3. 「**② コメントを追記**」を押す。実績側の「備考」ボタンが自動でクリックされ、
   ポップアップの各備考欄へ1欄ごとに0.5〜1.5秒の間隔をあけて追記される。
4. **⚠️ 内容を目視確認し、ポップアップの「登録する」は必ず自分で押す**。
5. 複数ページある場合（例 [合計：40件] 1/2ページ）は「次」でページを送り、2〜4を繰り返す。
6. 次の従業員に画面を切り替えて、1〜5を繰り返す。

## 👥 部署別の役割定義（運用ルール）

本ツールは、以下の3部署の分担で運用します。各担当は自分のタスクに責任を持ってください。

### 1. 【システム管理者・開発担当】

- **初回ビルド／デプロイ**：拡張機能を各 PC の Chrome へ導入する（上記「インストール」参照）。
- **保守（最重要）**：カイポケのシステムアップデート（UI 変更）でツールが停止した場合、
  `content.js` 先頭の `SELECTORS` を実画面に合わせて修正する。
  - セレクタはすべて `SELECTORS` に集約されているため、原則ここの修正だけで復旧できる。
  - Chrome の「検証（DevTools）」で対象要素の `id` / `class` を確認し、該当セレクタを更新する。
  - ⚠️ **カイポケ側の仕様変更による動作不良は自己責任**であるため、**社内で保守を行う**こと
    （カイポケ運営へのサポート依頼対象外）。
- コンプライアンス（`claude.md`）に反する改修（内部 API 通信の追加・スリープ削除等）は禁止。

### 2. 【サービス提供責任者・管理者】

- AI（ChatGPT 等）を用いて**訪問介護計画書の原案を作成**する。
- 作成した原案を、本ツールの **JSON フォーマットに変換・出力**する。
- 出力した JSON の**データ内容を確認**し、事務・入力担当へ引き渡す。

### 3. 【事務・入力担当スタッフ】

- 受け取った **JSON を拡張機能に貼り付け、自動入力を実行**する。
- **⚠️ 自動入力完了後、必ず人間の目で入力内容の最終確認を行う**。
- 誤登録がないことを確認したうえで、**カイポケ上で「登録（保存）」ボタンを押す**。
  - ⚠️ **自動化による誤登録は免責事項**となるため、**最終確認は必須**です。

## 🔧 保守：セレクタが合わなくなったら

「要素が見つかりませんでした（タイムアウト …）」というアラートが出た場合、
カイポケの画面構造が変わった可能性が高いです。【システム管理者・開発担当】が以下を行ってください。

1. カイポケの該当画面で右クリック →「検証」で DevTools を開く。
2. 対象の入力欄／ボタンを選択し、`id` や `class` を確認する。
3. `content.js` 先頭の `SELECTORS` の該当キーを、確認したセレクタに更新する。
4. `chrome://extensions` で拡張機能を「更新（再読み込み）」し、動作確認する。

> `content.js` の `SELECTORS` の各値は、実際のカイポケ画面に合わせて調整する前提の
> プレースホルダです。初回導入時にも実画面と突き合わせて設定してください。
